# OfficeTruck Driver (iOS)

Native driver app: Swift 6, SwiftUI, iOS 17+. Backend is the shared Supabase project (`../supabase`).

## Setup
1. `cp Config/Secrets.example.xcconfig Config/Secrets.xcconfig` and fill in the host and publishable key from `web/.env.local`. The file is git-ignored.
2. Open `OfficeTruckDriver.xcodeproj`. The project is generated from `project.yml` by XcodeGen, so edit `project.yml` (not the project's settings in Xcode) and run `xcodegen` after adding or removing files.
3. Command-line build: `xcodebuild -project OfficeTruckDriver.xcodeproj -scheme OfficeTruckDriver -destination 'platform=iOS Simulator,name=iPhone 16 Pro' -derivedDataPath build/DerivedData build`

## Conventions
- Build UI from stock SwiftUI only (`List`, `Section`, `LabeledContent`, `Label`, `Button` with system styles, `.alert`, `.sheet`, `ContentUnavailableView`, `ProgressView`). Don't create custom component views (badges, wrapper or styled row views); write the UI inline in each screen. One exception: the sign-in screen plays `Resources/Cargo.json` with the Lottie package (`LottieView`).
- SwiftUI and the Observation framework (`@Observable`, `@State`, `@Environment`). Don't use `ObservableObject` or Combine unless an API forces it.
- async/await for all I/O. Keep UI state on `@MainActor`.
- Talk to Supabase with the `supabase-swift` SPM package. Use the publishable (anon) key only; never ship the service-role key.
- Drivers sign in with phone OTP, then call the `claim_driver_logins()` RPC.
- Read driver data only through driver-scoped RPCs and RLS. Never decode or show load rates, `load_charges`, invoices or broker pay.
- Layout: `OfficeTruckDriver/App`, `Features/{Auth,Load,Trips,Pay,Me}`, `Core` (Supabase client, `DriverAPI`, models, offline queue).
- Stop and appointment times are wall-clock strings at the stop. Show them as written (`WallClock`); never convert them to the phone's time zone.
- Profile: drivers send a new CDL or medical card (`submit_my_driver_update`; nothing on the driver changes until an owner or admin accepts it on the web) and see their DQ file (`my_dq_file`, uploads with `add_my_dq_document`). DQ item status is worked out in the app like `web/lib/dq-rules.ts`.
- One screen, no tab bar: Trips is the root (Pay and Profile open as pages from its top-right toolbar). Rows say when the trip picks up, delivers (with "Stop 2 of 3" past two stops) or was delivered, and a search finds a trip by load number, city or carrier. It groups loads as Today (in transit, dispatched with pickup today or overdue, delivered today), Upcoming (dispatched, pickup on a later day) and Past (the rest, newest first), comparing pickup days as written. A dispatched or in-transit load whose time on the road (first appointment to the end of the last) overlaps another says why in orange on its row ("Picks up before QA-2002 delivers"), and the load screen opens with the full reason (where and when each one picks up and delivers) and Call dispatch: the office's dispatch warning (`web/lib/dispatch-format.ts`), which warns rather than refuses. Tapping a trip opens the load: Check in / Check out is the bottom primary button. Below the stops: Paperwork (one row each for BOL and POD: tap to add; once added, it says View, tap to view, even before it's uploaded (the copy on the phone opens, with "Uploading" or "Not sent yet · saved on this phone" under the name), and swipe left for View, Upload again or Remove; then lumper receipts and other) and Expenses (Add expense, `add_my_expense`, through the offline queue; Who paid: Me, paid back on the settlement, or Company, which needs a receipt and is sent so the office has it, never counted as owed to the driver; swipe left to view the receipt or remove one the driver added, `remove_my_expense`, which the server refuses once a paid pay statement covers the load). Each stop shows its pickup/delivery number and reference (PO) numbers, "Detention starts" while waiting (arrival, or the appointment when the driver is early, from the stop's `appointment_at`, plus the load's `detention_free_hours`; never the detention rate), and "Add odometer" or a tappable Odometer on the first pickup and last delivery once checked in (`set_my_stop_odometer`, needs signal). The load's details (broker, reference numbers, equipment, detention free hours), the driver's pay on it (rate, and the amount for per-mile or flat pay; a percent shows no dollars, since the app never reads the load's rate), dispatch's notes and the truck (unit, year/make/model, plate, VIN, odometer, inspection due and registration, from `my_load`'s `truck_details`; never its costs or ownership) open full height from the (i) toolbar button, swiped down to close, so the driver's actions come first.
- UI for drivers: big tap targets (≥ 44pt, prefer 56pt for primary actions), high contrast, Dynamic Type, system light/dark mode.
- Check in / Check out saves where the phone is (`CheckInLocation`, When In Use only, running only while a load that can be checked in is on screen) with the stop, for detention. No permission or no fix: the check-in still goes.
- Push notifications: once signed in, Trips asks for permission and the phone's token is saved with `register_my_push_token` (removed on sign-out). The office app pushes "New load …" when it dispatches a load to the driver (`web/lib/push.ts`, APNs key in `APNS_*` env vars); tapping it opens the load. Debug builds register as `sandbox`, others as `production`. Never put a rate in a push.
- Writes made with no signal (stop check-ins, document uploads, expenses) go through the offline queue and retry later. Anything queued shows as not sent (orange, with `icloud.slash`) only after a send actually failed; until then paperwork and expenses show a spinner and "Uploading", and stay that way until the reload brings them back from the server, so nothing flashes.
- Odometer: a reading can't be lower than the truck's last one (`truck_odometer` on `my_load`, from the truck's other loads or the office's own reading) or one earlier on the load. The check-in alert says the last reading; a lower one asks to enter it again or check in without it. The server enforces the same (`apply_stop_odometer`, hint `below_truck`); if it still turns the reading down, the queue keeps the check-in and drops the reading.
- Verify in the iOS Simulator on the latest iOS 26 runtime (iPhone 17 Pro): build, launch, take a screenshot and tap through the flow.
- Demo mode (Debug builds): launch with `-demo` (`xcrun simctl launch <device> com.officetruck.driver -demo`) to sign in with sample data from `Core/DemoBackend.swift`, with no SMS or server. Add `-two-carriers` to see a driver who drives for two companies, `-overlap` for two loads at the same time, `-offline` for check-ins and uploads that can't reach the server (demo uploads take 2 seconds, to see the spinner), or `-signed-out` to start at sign-in (no text is sent; any 6-digit code signs in).
